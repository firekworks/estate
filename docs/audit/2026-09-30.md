## Findings
1. Cap rate aliases yield on project cost. Maximum price only uses yield (market only limits opening offer). Four adverse scenarios only.
2. Listing writes overwrite latest source regardless of URL. Save is multiple requests without transaction. Reanalysis preserves property ID but recreates financing rows. No physical-asset dedup.
3. Rent/sale confidence manufactures low/high ranges from one manual input with zero comparables.
4. Kill switches prevent advancement in page state only; direct database updates bypass guard.
5. Portfolio and home label forecast cash flows as actual; no ledger, tenancy or forecast-error model.
6. Visitation/negotiation/plan are largely explanatory UI, not persistent workflows.
7. Vision upload calls backend, but failures swallowed; rerun helper not exposed; AI assessment treated as reviewed without human review.
8. Market aggregates user's underwriting inputs, not external comparable samples; no sample quality thresholds.
9. CSV splits quoted fields incorrectly, converts decimal dots by removing them, blanks become zero. Mobility skips malformed rows, truncates at 25000, mixed modes appear as pedestrians. Map overlay can drift from independently pannable iframe.
10. Provider status uses key presence as readiness, including unimplemented APIs. GVA marked ready but only external catalog link exists. No durable cost limits.
11. CSS consists of three competing layers, many 6–9px labels and low contrast. Large decorative empty states and misleading live indicators. App navigation only client state, no addressable asset URLs.
12. Entire page loads client components eagerly; queries load all nested history/images up to 150 properties. No refresh of expiring signed URLs while idle.
13. Eight financial unit tests; no workflow, API, RLS, import or responsive tests. No lockfile in baseline; CI uses npm install. Host Node22 vs required Node24.
14. npm audit reports critical Next.js next/og issue GHSA-vcvr-r3jv-pc5j, fixed >=16.3.6; application does not currently import next/og.
